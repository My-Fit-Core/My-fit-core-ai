## 요약

레퍼런스·T1 사진 없이 할 수 있는 정확도 측정을 K-Fashion 정답 라벨로 했다. 사진에서 YOLO로 옷을 찾고, 정답 박스와 짝지어진 옷을 잘라 **서비스 태깅 코드 그대로** 판정한 뒤 라벨과 비교했다. 대분류 89~90%(목표 90%에 근접), 소매 93~95%, 소분류 상위 3개 포함 80~81%는 쓸 만하다. 핏(55%)·소재(50%)는 약하고, **디테일은 쓸 수 있는 것이 없다.** **오프숄더 자동 판정은 실제 분포에서 대부분 오탐**이라 지금 추천 규칙에 그대로 쓰기 어렵다. 옷 한 벌 기준 7종 스타일 점수는 5종보다 낮다.

**주의**: K-Fashion은 사람이 입은 사진이다. 서비스 입력(바닥에 펼친 사진)과 달라서 T1 사진으로 다시 재야 한다.

## 측정 방법

- 스크립트 `scripts/eval_item_attributes_kfashion.py`
  - 표본: K-Fashion 23개 스타일 × 20장. **다듬기용**(시드 42, 460장, 정답 옷 668벌)과 **확인용**(시드 7, 다듬기용 사진을 뺌, 정답 옷 669벌)
  - 옷 자르기: 기존 카테고리 PoC와 같다(정답 박스와 IoU 0.5 이상으로 짝지어진 검출, 마스크 밖 흰색)
  - 판정: `app/pipeline/tagging.py`의 `_category_candidates`, `_attributes`, 스타일 점수를 그대로 호출. 대분류는 분석 파이프라인처럼 검출기 클래스로 정하고, 소매도 검출기 클래스(short/long sleeved)가 있으면 그 값을 쓴다
  - 옷 임베딩을 저장해 두고 매핑만 바꿔 다시 잴 수 있게 했다
- K-Fashion 라벨 → 우리 값 매핑(스크립트 상단): 소매 반팔·캡 → short, 긴팔·7부 → long / 핏 오버사이즈·루즈 → oversized, 노멀 → regular, 타이트 → slim(하의는 와이드·벨보텀·루즈 → oversized, 스키니 → slim) / 넥라인 오프숄더·원숄더 → true / 소재·프린트·디테일은 대응 표, 목록에 없는 소재(우븐 등)는 other / 소분류는 대응이 하나로 정해지는 것만(스커트·드레스는 기장으로)
  - 소재·패턴은 라벨이 여러 개일 수 있어, 판정이 그중 하나면 맞음으로 셌다
- **오프숄더 표본** (`--neckline-test 80`, 시드 11): 오프숄더·원숄더 사진 80장 + 아닌 사진 80장. 일반 표본에는 오프숄더가 3~5벌뿐이라 따로 뽑았다

### 스타일 점수 (옷 한 벌)

사진의 주 스타일이 연결 스타일인 옷을 정답으로 봤다(옷 하나가 코디 전체 스타일을 대표하지 않으므로 낮게 나오는 지표다).

| 설정 | 다듬기용 적중률 / AUC | 확인용 적중률 / AUC |
| --- | --- | --- |
| 5종 `prompts.item` (지금 서비스 5종) | 0.434 / 0.682 | **0.457 / 0.676** |
| 7종 `configs/styles.yaml` (태깅 v1) | 0.278 / 0.650 | 0.333 / 0.657 |
| 7종 문장 자동 고르기 (`configs/styles_tuned.yaml`) | 0.391 / 0.678 | 0.359 / 0.656 |

- 옷 한 벌 기준에서도 7종은 5종보다 낮다. 문장을 골라도 확인용에서 조금만 오르고(0.333 → 0.359) AUC는 그대로다. 약한 것은 미니멀(AUC 0.55)·Y2K/빈티지(0.61)다.
- `styles_tuned.yaml`은 실험 기록으로만 두고 서비스 설정(`styles.yaml`)은 바꾸지 않았다.

### 스타일 점수 offset

`scripts/tune_item_style_prompts.py`로 "옷별 1위 스타일 점수의 중앙값이 0.5"가 되는 offset을 다듬기용 옷 638벌에서 다시 구했다: **2.28**(확인용 1위 중앙값 0.52, 전체 평균 0.19, 0.5 넘는 점수 비율 0.12). 태깅 v1의 초안 2.3(사진 28장)과 거의 같아 **2.3을 유지**하는 근거로 쓴다. 점수의 뜻이 "확률"이 아니라 "상대적 세기"라는 점은 그대로다(태깅 v1 Report).
