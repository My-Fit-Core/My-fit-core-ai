## 요약

`app/pipeline/tagging.py`가 API v1 형식으로 결과를 내도록 바꿨다. 스타일 점수는 합 1인 비율 대신 **스타일마다 따로 0~1**로 매기고, 숨은 속성 `fit`·`off_shoulder`·`sleeve`·`material`·`details`를 문장 비교(zero-shot)로 판정한다. 불확실하면 `None`(모름)이다. 기준값은 모두 초안이라 T1 Flat Lay 사진으로 정확도를 재고 다시 정해야 한다.

## 변경 내역

- `app/pipeline/tagging.py`
  - `tag_item(image, bbox, mask, category=None)`: `category`를 주면(직접 등록한 신발·가방, 또는 검출기가 정한 대분류) 그 대분류 안에서만 소분류를 고른다
  - `TagResult`: `category`, `subcategory`, `category_candidates`(상위 3), `style_scores[{style_id, score}]`, `pattern`, `fit`, `off_shoulder`, `sleeve`, `material`, `details`, `embedding`
  - 문장 임베딩을 캐시해 옷마다 다시 계산하지 않는다(`_text_feats`)
- `configs/styles.yaml` (새 파일): 서비스용 스타일 판정 문장(옷 한 벌용, 7종 제안 기준)과 독립 점수 설정
- `configs/attributes.yaml`: 속성별 판정 문장과 기준값(`tagging`)
- `tests/test_tagging.py`: 가짜 문장 임베딩으로 판정 규칙(독립 점수, 대분류별 건너뛰기, 민소매 건너뛰기, 오프숄더 기준값, 모름 처리)과 설정 일관성을 확인. 통합 테스트도 v1 형식으로

## 판정 방법

| 항목 | 방법 | 적용 대분류 | 모름(None) 조건 |
| --- | --- | --- | --- |
| 스타일 점수 | `sigmoid(temperature × (스타일 문장 logit − "평범한 옷" 문장 logit) + offset)` | 전부 | 없음 |
| 패턴 | 8개 문장 중 1위 | 전부 | 없음(기존 동작 유지) |
| 소재 | 11개 문장 중 1위 | 전부 | 1위 확률 < 0.4 |
| 핏 | 대분류별 3개 문장(하의는 다리 폭) | 상의·하의·아우터·원피스 | 1위 확률 < 0.5 |
| 오프숄더 | [오프숄더, 양어깨 덮음] 쌍 | 상의·원피스 | 0.3 < 확률 < 0.6 |
| 소매 | [반소매, 긴소매] | 상의·원피스·아우터 (`sleeveless` 제외) | 1위 확률 < 0.6 |
| 디테일 | [있음, 없음] 쌍, 확률 ≥ 0.8 | 전부 | 정확도가 확인된 디테일만 판정(지금은 없음 → 항상 빈 목록) |

- 오프숄더의 `true` 기준을 낮게(0.6) 둔 이유: 놓치면 아우터와 안 어울리는 세트가 나가고, 잘못 붙이면 아우터 하나가 빠질 뿐이다(261125 Report §9-3).

## 주요 결정

| 결정 | 근거 | 대안과 버린 이유 |
| --- | --- | --- |
| 독립 점수 = "평범한 옷" 기준 문장과의 차이 | 스타일 수가 바뀌어도 기존 점수가 변하지 않음(11/25 결정) | 스타일끼리 softmax: 합 1이 돼 결정과 어긋남 |
| offset으로 점수 높이 조정 `[결정: 사용자]` | offset 0이면 거의 모든 점수가 0.1 미만 | temperature만 조정: 순위는 같고 전체가 0 근처에 몰리는 문제는 그대로 |
| 디테일은 검증된 것만 판정 | 작은 장식은 놓칠 수 있고, 잘못 붙이면 해가 큼(11/25 결정) | 전부 판정: 정확도 미확인 |
| 신발·가방은 핏·오프숄더·소매를 판정하지 않음 | 의미 없는 값이 추천 규칙을 건드리지 않게 | 전부 판정 |

## 점수의 뜻이 바뀌는 점 (확인 필요)

11/25 계획(§9-1)은 "이 스타일 문장 ↔ 평범한 옷 문장을 비교해 이 스타일일 확률"이었다. offset 0이면 그 뜻 그대로다(평범한 옷과 똑같이 닮으면 0.5). offset 2.3을 더하면 **평범한 옷 문장보다 덜 닮은 옷도 0.5를 넘을 수 있다**(logit 차이가 약 −4.6일 때 0.5). 즉 점수는 "확률"이 아니라 "스타일 느낌의 상대적 세기"가 된다. 추천은 점수 크기 비교로 쓰므로 영향이 작지만, 화면에 % 같은 확률로 보여 주려면 다시 정해야 한다 `[결정: 사용자]`.
