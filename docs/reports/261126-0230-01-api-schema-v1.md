## 요약

`app/schemas.py`를 v1으로 올렸다. 1차 멘토링 후 결정(`261125-2258-01-mentoring-feedback-ai-plan.md`)과 추구미 `style_id` 제안을 반영해, 스타일 점수를 `style_id`별 독립 점수로 바꾸고 숨은 속성·누끼 업로드·결과 상태를 넣었다. 예시 JSON(`docs/api-v1-examples.json`)을 두고 테스트로 스키마와 맞는지 확인한다. **백엔드와 아직 합의하지 않은 초안**이라 백엔드 확인 후 고칠 수 있다.

## 백엔드 확인이 필요한 것

- `client_item_key` 부여 방식(요청에 업로드 URL과 묶어 주는 방식으로 가정)
- `path`(업로드 후 저장 경로)를 요청에 줄 수 있는지. 없으면 `upload_url`에서 쿼리를 뺀 값을 `cutout_path`로 보낸다
- 공유 비밀키 헤더 이름, 콜백 HMAC 세부 규칙(02-specs §1 제안)
- 값 목록을 enum으로 받는지 문자열로 받는지, 패턴 값 8개(안건 7)
- `style_id` 번호(1~7)는 7종 합의 후 확정
- 숨은 속성·`warmth`·임베딩 저장 후 추천 요청에 다시 담아 주기

## 추천 담당과 맞출 것

- #115 레이어드 규칙은 `configs/recommend.yaml`의 `layered.aesthetic_keys: [vintage_layered]`로 켜진다. 7종 `style_ids.yaml`에는 `vintage_layered`가 없어서, **API로 들어온 요청에서는 레이어드가 켜지지 않는다.** 7종에서 빈티지 레이어드는 Y2K/빈티지·보헤미안으로 나뉘고 레이어드는 추구미가 아니라 추천 규칙으로 다루기로 했으므로(261125 Report §9-2), `aesthetic_keys`를 바꾸거나 조건에서 빼는 것을 추천 담당과 정한다 `[결정: 사용자]`.
- 이너 소분류(`inner_tshirt`, `sleeveless_inner`)가 #115에서 추가됐다. 2-2 소분류는 "초안 그대로 확정, 프론트도 맞춤"이었으므로 백엔드·프론트에 추가를 알려야 한다.
