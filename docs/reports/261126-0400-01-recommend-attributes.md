## 요약

API v1로 옷장 아이템에 들어오는 숨은 속성(`off_shoulder`, `fit`, `sleeve`, `material`)과 사용자가 고른 `warmth`를 추천 점수에 반영했다(261125 Report §9-2·9-3). 규칙은 모두 `configs/recommend.yaml`에 있고, 속성이 없으면(`None`) 기존과 똑같이 동작한다. **추천 담당(HandoA01)의 영역**이라 리뷰를 받고 머지한다.

## 변경 내역

- `recommend/scoring.py`
  - `Item`에 선택 필드 `sleeve`, `warmth`, `material`, `off_shoulder`, `fit` 추가(기본 `None`)
  - 옷 따뜻함 `item_warmth()`: 소분류 기본값 + 소매 보정(소매가 상황마다 다른 소분류만, 긴소매 +1) + 사용자 따뜻함(얇음 −1, 따뜻함 +1)
  - 비 오는 날: 소분류뿐 아니라 소재(`suede`, `leather`, `linen`)로도 감점
  - **오프숄더 규칙**: 오프숄더 상의·원피스 위에 블레이저·재킷은 걸림, 코트·패딩·가디건은 아우터 `fit`이 `oversized`가 아니면(모르면 포함) 걸림. 걸린 조합은 뺀다. 걸리지 않는 조합이 하나도 없으면(추워서 아우터가 꼭 필요) 보온을 우선해 남기고 `off_shoulder_outer_for_warmth`를 이유로 남긴다. 교체(swap) 후보도 같은 규칙
  - **원피스 + 바지**: 뼈대에 `[dress, bottom]` 추가. 하의는 `dress_layer_bottoms`(`jeans`, `slacks`)만. 원피스만 입는 조합도 그대로 후보
  - 교체: 상의 + 하의 코디에 원피스가 끼어들지 않도록, 지금 코디의 뼈대를 모두 담는 뼈대만 허용. 원피스 코디의 하의 교체는 받쳐 입는 바지만
- `configs/recommend.yaml`: `dress_layer_bottoms`, `rain.avoid_materials`, `warmth_adjust`, `off_shoulder`
- `app/main.py`: API 옷장 아이템의 속성을 `Item`으로 넘김
- `tests/test_recommend.py`: 오프숄더(다른 선택이 있으면 빠짐, 오버사이즈 아우터는 허용, 추우면 보온 우선, 교체 후보), 소매·사용자 따뜻함, 비 오는 날 스웨이드, 원피스 + 바지, 교체 뼈대 규칙

| 결정 | 근거 | 대안과 버린 이유 |
| --- | --- | --- |
| 오프숄더 규칙에 걸린 조합은 빼고, 그것밖에 없을 때만 남김 | 11/25 결정(블레이저·재킷 X, 코트는 오버사이즈일 때, 추운 날 보온 우선) | 감점만: 3세트를 채우려고 걸린 조합이 다시 나옴(테스트에서 확인) |

| 소매 보정은 정해진 소분류에만 | 니트·후드는 거의 긴소매라 소분류 기본값에 이미 들어 있음 | 모든 상의에: 니트가 이중으로 따뜻해짐 |
| 소재는 비 오는 날에만 사용 | 코디 따뜻함은 뼈대·아우터 합이라 신발(어그 등)이 들어가지 않음 | 소재로 따뜻함 보정: 신발 따뜻함 규칙이 먼저 필요 |
