## 요약

전체 와이어프레임을 팀 공유하며 미결 기획 항목들을 확정했다. 보조 추구미의 역할, 온보딩 사진 수, 통계 리포트 위치가 결정됐고, 디자인 마감일을 11/8로 연장했다. 참고 이미지가 5년 전 데이터라 현재 트렌드와 맞지 않는다는 문제가 제기됐으며, 타겟층을 2030에서 3040으로 바꾸는 방안이 논의됐다(미확정).

## 주요 결정

| 결정 | 근거 | 대안과 버린 이유 |
| --- | --- | --- |
| 보조 추구미 역할: 홈화면 태그 3개(메인 1 + 보조 2), 단독 선택으로 코디 재추천 | 메인은 디폴트, 오늘 분위기에 따라 보조로 전환 | 교집합(두 추구미 혼합) 방식은 복잡도 높아 보류 |
| 온보딩 추구미 사진: 총 15장 (추구미별 3장씩), 사용자는 최소 3개 ~ 최대 5개 선택 | 너무 많으면 선택 피로, 너무 적으면 가중치 계산 불안정 | 10장(2장씩), 20장(4장씩) 모두 검토 후 15장 채택 |
| 통계 리포트: 마이페이지에 위치, 의류별 착용 횟수 표시 | 와이어프레임에서 누락된 항목을 뒤늦게 확인 | 색상 통계는 프론트에서 처리 가능하나 우선순위 낮아 보류 |
| TPO: 1차 MVP 제외, 날씨 + 추구미 기반 추천만 | MVP 범위 집중. TPO는 2차 확장 | TPO 포함 시 카테고리 확정·추천 로직 복잡도 과다 |
| 디자인 마감: 11/8로 연장 (기존 11/5) | Figma 미숙 + 공통 컴포넌트 선작업 필요 | — |
| 소셜피드 노출 순서: 업로드 직후 상단, 탭 재진입 시 랜덤 새로고침 | 올린 직후 피드백 없으면 동기 저하. 랜덤 → 인기 쏠림 방지 | 좋아요 순 정렬은 채택 안 함(소셜 목적 아닌 레퍼런스 목적) |
| 추천 입력: 메인/보조 추구미 + 날씨 + 캘린더 일정 조합 | 백엔드 담당자가 일정도 반영해야 한다고 확인 | — |
| 옷장 등록 튜토리얼: 우선순위 낮음, 시간 남으면 추가 | 핵심 기능 완성도가 더 중요 | — |
