## 동작

1. 설정에 없는 카테고리·소분류 옷은 뺀다(`skipped_unknown_subcategory`).
2. 실효 기온 = 체감온도, 없으면 기온(풍속 기준 이상이면 보정). 기온 구간으로 목표 따뜻함 `[min, max]`, 덥고 습하면 낮춘다.
3. 후보 = 뼈대(상의+하의 / 원피스) × 아우터(추우면 필수, 아니면 없음 포함 전부) + 선택 슬롯(신발·가방·액세서리) 슬롯별 1개.
   - 선택 슬롯은 비 오면 피할 소분류가 아닌 것을 먼저, 그다음 추구미 점수로 고른다.
4. 날씨 점수 = 1 - (목표 범위와 따뜻함 거리 / 3), 비 오면 피할 소분류마다 감점. 추구미 점수 = 추구미 점수가 있는 옷의 평균. 최종 = 0.5 × 추구미 + 0.5 × 날씨.
5. 점수 순으로 고르되 이미 고른 코디와 핵심 옷(뼈대·아우터)이 겹치지 않게. 3종을 못 채우면 겹침을 1개씩 허용(`diversity_relaxed`).
6. 기온·체감온도가 모두 없으면 따뜻함 규칙을 끄고(날씨 기본점 1, 아우터 필수 없음) 비 규칙만 있는 값대로 적용한다. `weather_unavailable`. 결측 필드 이름은 `missing_weather`에 담는다.

## 결정이 바뀌면 설정 파일만 고치면 되는가

| 바뀌는 결정 | 설정만? | 고칠 곳 |
| --- | --- | --- |
| 안 A 유지, 소분류 추가·삭제·이름 변경 | 예 | `categories.yaml` + `recommend.yaml` `warmth`(의류 소분류만)·`rain.avoid`(이름이 바뀐 소분류가 있으면). 어긋나면 `test_warmth_matches_categories`, `test_rain_avoid_names_exist`가 실패해 알려 준다 |
| 대분류 이름 변경(예: `outerwear` → `outer`) | 예 | `categories.yaml`, `recommend.yaml`의 `bases`·`outer_slot`·`optional_slots`·`warmth` 키 |
| `dress`를 대분류에서 빼고 `top` 소분류로(안 B) | **아니오** | 원피스 한 벌이 상의·하의 두 자리를 채우는 규칙이 지금은 "대분류 `dress` = 뼈대 하나"로만 표현된다. 안 B면 "특정 소분류는 하의 없이 뼈대가 된다" 규칙을 코드에 추가해야 한다 |
| MVP 검출 범위(신발·가방·액세서리 자동 검출 여부) | 예 | 추천은 옷장에 있는 옷만 쓰므로 영향 없음. 슬롯을 빼려면 `optional_slots` |
| 기온 구간·따뜻함·바람·습도·비 기준·가중치·다양성 | 예 | `recommend.yaml` |
| 미세먼지 규칙 추가 | **아니오** | v0에는 규칙이 없어 코드 추가 필요 |
| 사용자 추구미 여러 개 선택 | **아니오** | 지금은 key 하나 |
