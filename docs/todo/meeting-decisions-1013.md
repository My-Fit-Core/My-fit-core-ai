## AI 담당 제안 (10/13 회의 안건)

위 열린 질문에 대한 AI 담당의 제안입니다. 확정이 아니라 회의에서 논의할 초안입니다.

- [x] **추천 로직 위치: AI 서버에 둔다** → 채택 (10/12 회의 안건 2)
  - 추천 품질이 임베딩과 추구미 점수를 어떻게 쓰느냐에 달려 있어, 만든 쪽이 맡아야 고치기 쉽다.
  - 백엔드에 두면 추천 코드를 패키지로 공유해야 해서 배포가 복잡해진다.
  - 규칙 기반이라 GPU가 필요 없어 AI 서버 부담이 작다.
- [x] **추천 엔드포인트 초안** (경로·필드는 `/v0/analyze`처럼 `/v0/` 접두사, snake_case) → 동기 응답, `job_id` 없음으로 채택. 경로 이름은 초안 유지 (안건 2, 4)
  - `POST /v0/recommend`: 코디 세트 3종 생성. 요청 `job_id`, `weather`, `aesthetic`, `wardrobe`, 응답 `sets[]`(각 세트는 `item_ids`와 `score`)
  - `POST /v0/recommend/swap`: 슬롯 1개 대체 후보. 요청은 위 필드에 `outfit_item_ids`와 교체할 `slot`(category 대분류)을 더하고, 응답은 `candidates[]` 랭킹
  - 필드 이름과 응답 형식은 `app/schemas.py` 스타일을 따르며, 합의 후 v1에서 확정
  - 열린 질문: 추천은 규칙 기반이라 빠르므로 동기 응답으로 할지(이 경우 `job_id` 불필요) 회의에서 결정
- [x] **입력: 백엔드가 모두 담아 보낸다** → 채택. 날씨는 기온·강수 형태·습도·풍속·강수확률 (안건 3). 옷장 아이템에 임베딩을 담을지는 `TBD`(T3)
  - 요청에 날씨 snapshot(온도, 습도, 강수확률, 강수형태), 선택한 추구미 key, 옷장 아이템 목록(카테고리, 색, 패턴, 추구미 점수, 임베딩)을 담는다.
  - AI 서버는 날씨를 조회하지 않고 DB에도 직접 접근하지 않는다(MVP 기준).
- [x] **처리 시간과 방식** → 채택. 분석 결과는 콜백 `[확인]`, 추천은 동기 (안건 4, 5)
  - 처리 시간은 "워밍된 상태의 추론 시간"으로 측정한다(콜드 스타트, 이미지 다운로드, 업로드는 제외하고 따로 기록).
  - 비동기 방식은 분석(`/v0/analyze`) 기준이다. 콜백과 polling 중 선택은 회의에서 정한다.
  - 추천의 동기 여부는 위 "추천 엔드포인트 초안"의 열린 질문에서 정한다.
- [ ] **옷장 데이터 전송량**
  - MVP는 추천 요청에 임베딩을 담아 보내는 방식을 제안한다.
  - 옷장 최대 벌 수와 임베딩 차원에 따라, 어느 기준을 넘으면 AI 서버가 pgvector를 직접 조회하는 방식으로 바꿀지 회의에서 정한다.
- [ ] **모델 버전 원칙**: `model_version`이 다른 임베딩은 서로 비교하지 않고 재계산한다.
- [ ] **입력 이미지 규칙 확정**: EXIF 회전 처리, 최대 해상도, bbox 좌표 기준(원본 해상도 기준인지)을 정한다. → 일부 결정: 형식·용량·EXIF·bbox 기준은 아래 "안건 9" (10/12 회의 안건 9). 최대 해상도(긴 변 2048px 유지 여부)는 남음
- [x] **TPO는 1차 MVP에서 제외**하고 날씨 + 추구미 기반 추천만 한다. TPO는 2차 확장으로 둔다. → 채택 (안건 6). `02-specs.md` §6은 T24에서 수정, `03-product-plan.md`는 T22
  - 메모: 채택되면 `02-specs.md` §6("추천 엔진이 지원해야 할 것"의 TPO 반영)과 `03-product-plan.md`(날씨 × 추구미 × 일정 표현)를 같이 수정해야 한다.
- [x] **추구미 개수와 목록 확정**: 개수는 가정하지 않고, 목록은 `configs/aesthetics.yaml` 설정으로 받는 구조를 유지한다. (위 "15대 추구미 목록 확정" 질문과 같은 안건) → 기본 5개 + 마이크로 트렌드 2계층 구조 합의 (안건 1)
- [x] **`requirements.txt` 버전 고정 여부**: 현재 `>=`라서 설치 시점마다 버전이 달라질 수 있다. 고정할지, 고정한다면 시점은 언제인지 정한다. → 현재 버전으로 고정 완료, 방식은 개발 시작 즈음 협의 (안건 10)

- 안건 9 — 입력 이미지 규격
