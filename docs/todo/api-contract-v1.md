## 백엔드 전달용 질문 초안 (T3, 2026-11-23)

> 10/12 회의 답변 이후 남은 것만 모았다. `[제안]`은 AI 파트 제안이고 확정이 아니다. 답을 받으면 위 "열린 질문"에 체크하고 `meeting-decisions-1013.md`에도 반영한다.

**AI 파트가 먼저 드리는 답**
1. 사진 1장당 최대 옷 수(`max_det`)는 **6벌**입니다. 누끼 업로드 URL도 최대 6개로 보내 주세요. 검출이 URL 개수보다 많으면 신뢰도 높은 순으로 URL 개수까지만 돌려드립니다.
2. 입력 규격은 회의 결정대로 JPEG/PNG/WebP, 최대 20MB로 구현했습니다. 긴 변 상한(현재 2048px)은 AI 쪽에서 다시 정해 알려드리겠습니다.

**백엔드에 여쭙는 것**
1. `client_item_key`: 누끼 업로드 URL과 1:1로 묶이는 키로 이해했습니다. 요청에 `[{client_item_key, upload_url}, ...]` 목록으로 주시고, AI 서버가 검출된 옷을 신뢰도 순으로 앞에서부터 배정하는 방식이면 될까요? `[제안]`
2. AI 서버 인증: 백엔드 → AI 서버 요청에 공유 비밀키 헤더(예: `X-AI-Server-Secret`)를 넣는 방식을 제안합니다. `[제안]` 다른 방식을 원하시면 알려 주세요.
3. 콜백: 콜백 URL은 분석 요청마다 `callback_url`로 받으면 될까요, 아니면 고정 URL인가요? 콜백 요청 인증도 같은 공유 비밀키 헤더로 할까요? `[제안]`
4. 임베딩("임베딩 DB 따로 분류"의 의미): `[제안]` 분석 결과에 옷마다 `embedding`을 담아 드리면 백엔드가 pgvector에 저장하고, 추천 요청 때 옷장 아이템마다 다시 담아 보내 주시는 방식입니다. 임베딩 차원과 `model_version`은 모델 확정 후(T11) 알려드립니다. 다르게 생각하신 방식이 있으면 알려 주세요.
5. 에러 코드: 임시안 7종(`WORKER_TIMEOUT`, `MODEL_UNAVAILABLE`, `STORAGE_UNAVAILABLE`, `INTERNAL_ERROR`, `CALLBACK_TIMEOUT`, `NO_GARMENT_DETECTED`, `ANALYSIS_FAILED`)으로 구현하겠습니다. 이미지 규격 위반(형식·용량·손상 파일)은 우선 `ANALYSIS_FAILED`로 보내는데, 사용자 안내 문구를 다르게 하려면 전용 코드(예: `INVALID_IMAGE`)가 필요할지 확인 부탁드립니다.
6. 상태값: 작업 상태(대기·진행중·완료·실패)와 결과 상태(`succeeded`/`partial_failed`/`failed`)를 응답에서 `job_status`, `result_status` 두 필드로 나눠도 될까요? `[제안]`
7. 카테고리: 대분류에 원피스(`dress`)를 추가하면 좋겠습니다(1020 여성 타겟, 추천에서 상의+하의 두 자리를 한 벌로 채움). `[제안]` 소분류 목록 초안은 별도로 드리겠습니다(`docs/todo/category-taxonomy.md`).
